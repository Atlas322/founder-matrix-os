# fm:update - сешний төлөв, миний task-ууд, өдрийн дүгнэлт

Нэг командаар гурван зүйл хийнэ:
- **(A)** энэ дүрийн төлөвийг `STATUS.md`-ийн өөрийн мөрөнд шинэчилнэ;
- **(B)** бусад дүрийн мэдээнээс өөрт хамаатайг уншина, мөн өөрийн нээлттэй task-уудыг жагсаана;
- **(C)** хүсвэл өдрийн дүгнэлтийн атом бичнэ.

Vault: `${user_config.vault_path}` (доор `<V>`). Төхөөрөмж: `${user_config.device}`. Дүрэм: `<V>/_system/BOOT.md`.

`$ARGUMENTS`:
- текст өгсөн бол төлөвийн өгүүлбэр болгон ашигла;
- «өдрийн дүгнэлт», «дүгнэлт» эсвэл «day» үг агуулсан бол (C)-г мөн гүйцэтгэ.

> v0-д Discord, relay мэдэгдэл **байхгүй** (v0.2-т нэмэгдэнэ). Юу ч бүү илгээ. Нэг эх үүсвэр нь vault-ийн `_system/STATUS.md`.

## 0. Бэлтгэл

1. Огноо, цагийг `date +%F` болон `date +%H:%M`-ээр ав. Хэзээ ч бүү таа.
2. **Дүрийг тодорхойл.** Сешний context-д байгаа `Дүр: <slug>` мөрөөс ав.
   - Хэрэв байхгүй бол: «Дүр тогтоогоогүй байна. `/fm:role <slug>` ажиллуулах уу, эсвэл `${user_config.member}` нэрээр шинэчлэх үү?» гэж асуу.
   - Хариу ирэхээс өмнө STATUS-д бүү бич.
3. **Хувийн горимыг шалга.** Хэрэв context-д `PRIVATE сешн` гэж байвал, эсвэл дүрийн note-д `private: true` байвал (жишээ нь «Санхүү» дүр) доорх 🔒 хэсгийг дага. Ингэхэд (A) болон (C) өөрчлөгдөнө.

## (A) Төлөв шинэчлэх

### A1. Нэг өгүүлбэр бэлдэх

Ярианаас (эсвэл `$ARGUMENTS`-аас) дараах гурвыг гарга:
- **Хийсэн:** энэ сешнд бодитоор дууссан зүйл (1-3 зүйл).
- **Зогссон:** одоо юун дээр зогссон, юу хүлээж байгаа (хэнээс).
- **Дараагийн алхам:** дараагийн сешн юунаас эхлэх вэ.

Мөн энэ сешнд үүсгэсэн атом, task-ийн холбоосыг цуглуул.

### A2. STATUS.md-ийн өөрийн мөрийг шинэчлэх

`<V>/_system/STATUS.md` нь бүх дүрийн нэг самбар. Энэ нь гурван баганатай хүснэгт бөгөөд **дүр бүр нэг мөртэй**:

```markdown
| Дүр | Сүүлд (огноо · төхөөрөмж) | Хаана зогссон → дараагийн алхам |
|---|---|---|
| [[00 GTD]] | YYYY-MM-DD HH:MM · <төхөөрөмж> | <хийсэн> → <зогссон> → <дараагийн алхам> · [[атом]] |
```

**Журам:**
1. Файлыг Read-ээр унш.
2. Эхний баганаас өөрийн дүрийн note-ийн холбоосыг хай. Жишээ нь `[[00 GTD]]`. Энэ нь context-ийн `Дүр: <slug> ([[.../00 GTD]])` мөрөнд байгаа note-ийн нэр.
   - **Мөр олдвол:** зөвхөн тэр мөрийн 2, 3-р нүдийг Edit-ээр соль.
   - **Мөр олдохгүй бол:** хүснэгтийн сүүлийн мөрийн дараа шинэ мөр нэм.
3. Frontmatter-ийн `updated:` талбарыг `YYYY-MM-DD HH:MM` болгож шинэчил.
4. Файл огт байхгүй бол дараах байдлаар үүсгэ:
   - frontmatter: `type: system`, `updated:`;
   - `# 🧭 STATUS - дүр бүр хаана зогссон`;
   - нэг мөр тайлбар;
   - дээрх хүснэгтийн толгой ба өөрийн мөр.

**Нүдний дүрэм:**
- Нэг мөрөнд багтаана. Мөр шилжүүлэлт хэрэглэхгүй.
- `|` тэмдэгт хэрэглэхгүй. Хэрэглэх нь хүснэгтийг эвдэнэ, wikilink-ийн `|alias` ч мөн адил.
- ≤250 тэмдэгт.
- Агуулга биш, **холбоос**: дэлгэрэнгүйг атомд бич. Хэрэв атом хараахан байхгүй бол эхлээд `/fm:track` ажиллуулж, дараа нь холбоосыг энд тавь.

**Хориг:**
- Бусад дүрийн мөрөнд хэзээ ч бүү хүр.
- Файлыг бүхэлд нь Write-аар дарж бичихгүй.
- 🔒 `private: true` дүрийг энд хэзээ ч бичихгүй.

### A3. Лог мөр

`<V>/_system/logs/<огноо>.md`-д нэг мөр нэм. Read → Edit-ээр, файлын төгсгөлд нэмнэ. Файл байхгүй бол үүсгэ.

```
- **HH:MM** · <дүр> → update · [[_system/STATUS]] · [[атом]] · [[task]]
```

## (B) Унших ба миний task-ууд

### B1. Бусдын мэдээ

Дараах хоёрыг унш:
- `STATUS.md`-ийн бусад мөр;
- өнөөдрийн логийн мөрүүд.

Хэрэв **энэ дүрд хамаатай** зүйл байвал хэрэглэгчид ≤3 мөрөөр хэл. Хамаатай зүйл гэдэг нь:
- өөр дүр энэ дүрээс юм хүлээж байгаа;
- давхардсан ажил;
- энэ дүрийн хүрээнд гарсан шийдвэр.

Хамаатай зүйл байхгүй бол юу ч бүү хэл.

### B2. Нээлттэй task-ууд

Дараах дарааллаар хайна:

1. `<V>/02-GTD/tasks/`-д Grep хий:
   - pattern: `^owner:\s*["']?(<slug>|@?<дүрийн нэр>)["']?\s*$`
   - Grep tool ашигла, `output_mode: files_with_matches`.
2. Олдсон файл бүрийн frontmatter-аас дараах талбаруудыг унш: `status`, `priority`, `due`, `project`.
3. Шүүлт хий:
   - `status` нь `completed`, `cancelled` (хуучин `done`) бол хасна;
   - бусад нь нээлттэй гэж тооцогдоно.
4. Хүснэгтээр харуул. Эрэмбэ:
   - эхэнд хугацаа хэтэрсэн (`due` < өнөөдөр, ⚠️ тэмдэгтэй);
   - дараа нь priority (`high` → `medium` → `low`; хуучин note-д 🔴 → 🟡 → 🟢);
   - дараа нь `due`.

   | Task | Төлөв | Чухал | Хугацаа | Төсөл |
   |---|---|---|---|---|

5. Хэрэв энэ сешнд аль нэг task дууссан бол хэрэглэгчээс зөвшөөрөл ав. Дараа нь тэр task-ийн:
   - `status: completed` болон `updated:` талбаруудыг шинэчил;
   - `## Хүргэсэн` хэсэгт нэг мөр нэм.

Дүргүй сешнд `owner: me` болон `owner: "@${user_config.member}"`-ийг хай.

## (C) Өдрийн дүгнэлт (зөвхөн хүсэлтээр)

### C1. Эх сурвалж

Дараахыг унш:
- өнөөдрийн лог (`_system/logs/<огноо>.md`);
- өнөөдөр үүссэн атомууд (`06-Atomic/**/<огноо> - *`);
- `STATUS.md`-ийн өөрийн мөр;
- энэ ярианы гол утга.

### C2. Нэрлэх

Өдрийн хамгийн чухал **1 утсыг** сонго. Энэ нь ойлголт, шийдвэр эсвэл ахиц байж болно. Олон зүйл болсон ч нэгийг нь ялгаж гарга.

### C3. Атом бичих

Зам: `06-Atomic/knowledge/YYYY-MM-DD - odriin-dugnelt-<slug>.md`

```yaml
---
date: YYYY-MM-DD
updated: YYYY-MM-DD
type: atomic
kind: daily-conclusion
tags: [atomic, daily-conclusion]
confidence: stated            # хэрэглэгчийн өөрийн үг бол; агентын дүгнэлт бол medium
sources: ["[[_system/logs/YYYY-MM-DD]]", "[[02-GTD/daily/YYYY-MM-DD]]"]
role: <slug>
projects: []                  # өдрийн гол утга төсөлд хамаарвал
areas: ["[[04-Areas/AI Team/ai-workers/<дүрийн note>]]"]
supersededby: []
ai-first: true
---
```

Атомын бие:
- `# <Өдрийн гол утга - нэг өгүүлбэр>`
- `## For future agent` (2 өгүүлбэр)
- `## Дүгнэлт`: 2-4 өгүүлбэр. Хэрэглэгчийн өөрийн үг, хэллэгээр бич (ярианаас түүж ав). Агентын шинжилгээ бүү бич.
- `## Өдрийн тоо`: N атом, N task дууссан, N шинэ. Тоог зөвхөн бодит эх сурвалжаас ав.
- `**Холбоос:**`: өдрийн гол атом, task-ууд.

Ижил нэртэй атом өнөөдөр аль хэдийн байвал шинээр бүү үүсгэ. Байгаа атомыг баяжуул.

### C4. Холбох

- Өдрийн note (`02-GTD/daily/<огноо>.md`) байвал түүний `## 🌙 Оройн дүгнэлт` хэсэгт (хуучин загварт `## 🌙 Evening Review`) `[[атом]]` холбоос нэм. Байхгүй бол `/fm:daily`-ийн журмаар үүсгэ. Хэрэглэгчийн бичсэн мөрийг бүү өөрчил.
- Лог мөр:

  ```
  - **HH:MM** · <дүр> → дүгнэлт: [[06-Atomic/knowledge/YYYY-MM-DD - odriin-dugnelt-<slug>]]
  ```

### C5. Хэрэглэгчид харуулах

Дүгнэлтийг хэрэглэгчид харуулаад «засах уу?» гэж асуу.

## 🔒 Хувийн дүр (жишээ нь «Санхүү»)

Хувийн мэдээлэл vault-аас **хэзээ ч гарахгүй**, мөн STATUS, лог, атомд орохгүй. Иймд дараах байдлаар ажиллана:

- **(A) STATUS:** `STATUS.md`-д огт бүү бич. Мөр үүсгэхгүй, засахгүй.
- **Төлөв:** «хийсэн → зогссон → дараагийн алхам» мэдээллийг дүрийн хувийн хавтас доторх `_state.md`-д бич. Санхүү дүрийн хувьд энэ нь `04-Areas/Business/finances/private/_state.md`. Энэ файл `type: state`, `private: true`, `ai-first: true` талбаруудтай.
- **Лог:** `_system/logs/`-д огт бичихгүй (BOOT: хувийн мэдээлэл логт орохгүй).
- **(B) Task-ууд:** жагсааж болно. Гэхдээ дүн, данс, байгууллагын нэрийг хүснэгтэд бүү давт. Гарчгийг л харуул.
- **(C) Өдрийн дүгнэлт:** `06-Atomic` руу **бичихгүй**. Хэрэглэгч хүсвэл `_state.md`-д огноотой нэг догол мөр нэм.

## Тайлан (хэрэглэгчид)

```
✅ STATUS: <slug> мөр шинэчлэгдэв - «<нэг өгүүлбэр>»
📋 Нээлттэй task: N (⚠️ хэтэрсэн M)
👀 Бусдаас: <≤3 мөр эсвэл юу ч биш>
🌙 Дүгнэлт: [[...]] (хүссэн бол)
```

## Хориг

- Бусад дүрийн STATUS мөр, task, лог мөрийг засахгүй.
- Зохиохгүй. Тоо, огноо, хүлээж буй хүнийг зөвхөн бодит эх сурвалжаас авна.
- Юу ч илгээхгүй, нийтлэхгүй.
- Vault-аас гадуур бичихгүй.
- `.obsidian/`-д хүрэхгүй.
